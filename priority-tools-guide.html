重点工具页使用指南

这份指南面向第一次使用 Ymir Tool 的用户，集中说明十个高频工具的适用场景、建议步骤、常见误区和相关入口。它的目标不是堆关键词，而是帮助用户更快判断应该打开哪个工具、怎样处理输入内容，以及遇到结果异常时如何排查。

重点工具页指南

打开 JSON 格式化工具
提示：处理接口、日志、配置、文本或时间数据时，建议先复制一份原始内容；如果内容包含账号、令牌、手机号、邮箱等敏感信息，请先脱敏后再粘贴到页面中。

快速入口

  • JSON 格式化：整理接口返回、配置片段和日志数据。
  • MD5 工具：计算文本摘要，用于一致性对比。
  • Base64 编解码：处理接口参数、文本编码和 Data URI 内容。
  • JavaScript 格式化：阅读压缩脚本和整理代码片段。
  • URL 编码/解码：处理中文参数、回调地址和特殊符号。
  • 文本对比：比较配置、文案、代码和日志差异。
  • 字数统计：检查标题、摘要、表单限制和文章长度。
  • 正则表达式测试：验证提取、校验和匹配规则。
  • 科学计算器：进行临时公式、比例和数值核对。
  • Unix 时间戳转换：排查接口、日志和数据库时间字段。

JSON 格式化：先校验，再定位层级

JSON 工具适合接口调试、日志排查和配置检查。使用时先粘贴完整 JSON，再格式化查看缩进层级。如果页面提示格式错误，优先检查双引号、逗号、括号闭合、数组和对象是否完整。

  1. 粘贴接口返回值、配置片段或日志中的 JSON。
  2. 点击格式化，查看对象和数组的层级。
  3. 需要传输或保存时，再使用压缩或转义功能。

常见误区：把 JavaScript 对象当成 JSON、末尾多逗号、字符串没有闭合、复制时少了开头或结尾括号。

相关入口：JSON 格式化、JSON 压缩转义、JSON 格式化指南

MD5：用于摘要对比，不用于保护密码

MD5 适合快速生成文本摘要，用于判断两段内容是否一致。它不是可逆加密，也不适合单独用于密码存储。对比 MD5 前，要确认大小写、空格、换行符和字符编码完全一致。

  1. 粘贴需要计算摘要的文本。
  2. 生成摘要后复制结果。
  3. 把摘要与目标值对比，若不同，回到原文检查空格和换行。

常见误区：以为 MD5 可以解密，或忽略了末尾换行导致结果不一致。

相关入口：MD5 工具、SHA/SHA256、哈希工具指南

Base64：它是编码，不是加密

Base64 常用于把文本或二进制内容转换为便于传输的可见字符。它可以用于接口参数、邮件内容、图片 Data URI 或简单配置传递，但不能提供保密能力。

  1. 确认要执行编码还是解码。
  2. 粘贴完整内容，注意不要漏掉末尾填充字符。
  3. 解码后如果乱码，检查原始文本编码和复制完整性。

相关入口：Base64 编解码、图片转 Base64、编码转换指南

JavaScript 格式化：阅读代码前先保留原文

JavaScript 格式化适合阅读压缩脚本、整理片段和排查括号层级。正式项目中不要直接覆盖原始文件，建议先复制一份再处理。

  1. 粘贴脚本片段或压缩后的代码。
  2. 格式化后检查函数边界、缩进、括号和字符串。
  3. 如果还要压缩，先确认格式化后的代码逻辑没有被修改。

相关入口：JS 格式化/压缩、HTML 格式化、代码格式化指南

URL 编码/解码：避免重复编码

URL 编码用于处理中文、空格、特殊符号和查询参数。排查接口问题时，要确认你处理的是整个 URL，还是单个参数值；重复编码会导致结果难以阅读。

  1. 粘贴完整 URL 或单个参数值。
  2. 根据场景选择编码或解码。
  3. 检查空格、百分号、等号、连接符和中文是否符合预期。

相关入口：URL 编码/解码、Unicode/ASCII 转换、编码指南

文本对比：先统一格式，再比较差异

文本对比适合比较配置、文案、接口返回值、日志和代码片段。若整段都显示不同，通常不是内容完全变化，而是换行符、缩进、空格或不可见字符不一致。

  1. 把旧版本放在一侧，新版本放在另一侧。
  2. 先查看新增、删除和修改的行。
  3. 差异过多时，先统一缩进、空格和换行后再比较。

相关入口：文本对比、文本替换、文本工具指南

字数统计：适合发布前检查长度

字数统计可用于检查标题、摘要、产品描述、公告、社交媒体文案和表单输入限制。中文、英文和符号的统计口径可能不同，正式发布前应结合目标平台规则复核。

  1. 粘贴待统计文本。
  2. 查看字符数、行数和词数等结果。
  3. 发布前删除重复换行和多余空格。

相关入口：字数统计、文本对比、文本工具指南

正则表达式测试：从小样本开始

正则表达式适合做表单校验、日志提取和文本清洗。建议先准备几条应当匹配和不应当匹配的样例，再逐步增加边界条件，避免规则过宽或过窄。

  1. 输入待匹配文本和表达式。
  2. 观察匹配结果是否覆盖预期样例。
  3. 再补充边界样例，例如空值、特殊符号和多行文本。

相关入口：正则表达式测试、正则语法速查、常见问题排查

科学计算器：快速核对，重要结果要复核

科学计算器适合临时计算公式、比例、折扣、幂运算和简单数值核对。涉及财务、工程、医疗等高风险结果时，不应只依赖在线计算器，应使用专业系统或人工复核。

  1. 输入表达式或使用页面按钮。
  2. 复杂公式分步计算，减少括号错误。
  3. 复制结果前确认小数位、单位和取舍规则。

相关入口：科学计算器、数据大小换算、计算换算指南

Unix 时间戳：重点确认秒、毫秒和时区

Unix 时间戳常见于接口、数据库、日志和消息队列。排查时间问题时，最常见的问题是把秒级和毫秒级混用，或把 UTC 时间和本地时间混淆。

  1. 确认时间戳是 10 位左右的秒级，还是 13 位左右的毫秒级。
  2. 转换后同时记录原始值和显示时间。
  3. 跨地区协作时，说明使用的时区，避免误判时间差。

相关入口：Unix 时间戳转换、世界时间、时间工具指南

下一步如何选择工具？

如果你正在排查接口问题，通常先使用 JSON 格式化、URL 编码和时间戳转换；如果正在整理文本，优先使用文本对比、字数统计和文本替换；如果正在处理代码片段，可以从 JavaScript、HTML、CSS 和 SQL 格式化工具开始。

如何选择优先工具：按任务而不是按工具名

重点工具页的作用是让用户从具体任务出发快速进入正确工具，而不是在几十个工具名之间猜测。每个可索引页面都应有明确任务、可操作说明、相关入口和复制前复核清单。选择工具时可以先问三个问题：输入是什么格式，目标是阅读、转换、校验还是比较，输出是否会进入生产系统。

任务首选入口配套复核
接口返回读不懂JSON 格式化用 JSON 指南 检查语法和字段类型。
参数乱码或链接异常URL 编码/解码确认完整 URL、路径和 query value 的边界。

核对文件或配置是否一致MD5 摘要安全发布优先使用 SHA-256 或官方签名。

三类用户路径

  1. 开发调试：先用 JSON、URL、Base64、Unix 时间戳工具定位数据形态，再回到代码或接口文档确认契约。
  2. 内容发布：先用文本对比和字数统计检查差异、长度、空格和变量，再进入目标平台预览。
  3. 运维复核：先用 MD5、时间戳、文本对比检查文件、日志和配置，再在受控系统执行正式变更。

不要把工具选择变成批量复制

同一段输入连续经过多个工具时，要在每一步保存原文、记录转换原因，并确认输出仍然符合预期。尤其是 Base64、URL 编码和 JSON 转义组合使用时，重复编码会让问题更难定位。若无法解释每一步为什么必要，应停止处理，回到原始数据源。

站点审核角度的维护规则

只把有明确说明、真实示例、错误排查和内链关系的页面保持为可索引广告页。纯导航、重复模板、短说明和未维护长尾页应继续保持 noindex，避免重新扩大低价值内容面。
