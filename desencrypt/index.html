DES Ciphertext Format Reference

Document DES ciphertext mode, IV, padding, encoding, and key derivation so historical data can be identified before migration.

  • Use DES only to reproduce or inspect legacy formats.
  • DES Ciphertext Format Reference: Paste non-sensitive sample data first; do not paste secrets, tokens, customer data, or production keys.
  • DES Ciphertext Format Reference: For new security-sensitive work, use a reviewed modern cryptographic design outside this compatibility helper.

Fields to capture from an old payload

DES execution is disabled on this page. Use the reference to describe the format around an existing ciphertext rather than guessing from the bytes.

  • Raw bytes, hexadecimal, Base64, or a custom envelope.
  • Cipher mode and whether an IV is stored, derived, fixed, or omitted.
  • Padding such as PKCS#5/PKCS#7, zero padding, or no padding.
  • Text encoding before encryption and after decryption.
  • Key derivation, salt, iteration count, and library/version.

Why the ciphertext alone is insufficient

Two systems can both say “DES” while producing incompatible results because the mode, padding, IV, KDF, and serialization differ. A known-answer test vector is more reliable than a filename or algorithm label.
